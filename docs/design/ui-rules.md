# UI Rules

These rules prevent KRYOS from becoming visually confusing.

## General Rules

- No page should look like a giant form by default.
- Editing must be an intentional mode.
- Repeated actions should use icons when the meaning is clear.
- Buttons should not overflow on mobile.
- Text must not overlap or escape containers.
- Avoid duplicate controls with the same meaning.

## Career Rules

- Roadmap view is read-first.
- Only one roadmap-level pencil opens editing.
- Checklist text is read-only unless the roadmap editor is open.
- Checklist checkoff stays available in read mode.
- Delete actions are only visible in edit mode.

## Today Rules

- Today is an execution cockpit.
- Inbox owns unscheduled tasks.
- Upcoming owns scheduled future work.
- Do not duplicate Inbox with another visible "Anytime" tab.

## Habits Rules

- Habits should feel visual.
- Matrix, streak, strength, pace, and drift cause should support motivation.
- Habit tracking should use the same task record truth as Today.

## Journal Rules

- Journal should calm the mind.
- Inputs are acceptable because journaling is an input-heavy page.
- Truth filter should show saved state clearly.

## Progress Rules

- Progress is read-only.
- No manual input should be required.
- Visuals must answer a decision or reveal a pattern.

## Settings Rules

- Settings should be clear and trustworthy.
- Security copy must not overpromise encryption.
- Destructive actions must require confirmation.
