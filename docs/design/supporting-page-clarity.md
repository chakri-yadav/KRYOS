# Reward, finance and storage clarity

## Rewards

One shared selected-day summary supplies dated score, earned points and current
wallet context. The existing summary owner is reused by both reward render paths;
presentation refresh does not create a second summary. Archived earnings are
labelled when they precede the active wallet period.

Current eligibility is evaluated at the operating clock date, even in history.
The presentation reads the existing eligibility and reservation owners and shows
points needed, cooldown end and qualified-day blockers together. Catalogue,
qualification, scoring, caps, reset behavior and redemption request/retry logic
are unchanged. Support and basic needs remain unrestricted.

Retained assessment audit shows behavior date, recorded change time, prior/next
earned credits and the stored reason. Missing reasons are explicitly unrecorded;
the UI does not infer a specific source or manufacture ledger entries.

## Money

Current balances and ledger positions retain their domain calculations. The
selected personal date defaults completed-event forms and scopes an optional
contact/payment/ledger view; it does not rewind current positions. Historical
checkpoints retain their own verification dates.

The local distribution promotes the existing follow-up/setup action. The hosted
distribution retains its existing call brief, reconciliation and ledger actions
and adds scope clarification without introducing a second next-action panel.
Balance-settled presentation reads the existing owner's position; integer-cent
math and statement reconciliation are unchanged.

## Settings

Rows distinguish task-owned daily records, separately stored foundation/legacy
journal blocks, Career and Marketing. A task receipt never confirms another
block. Local Marketing/Career destinations remain separate from hosted copies;
hosted Marketing holds approved aggregate snapshots only.

Successful existing task/Career save responses and applied remote blocks record
a confirmation time in session memory, scoped by account, mode and workspace.
No new cloud operation or stored schema is introduced. Pending/error/disconnected
states suppress current confirmation claims. Other blocks without tracked
confirmation are labelled separately. Status refresh replaces only its owned
section so credential/input drafts elsewhere remain intact.

A JSON download request records only initiation time and format/software version
for the active mode; it does not prove the file was saved. A local database/files
backup displays only an accepted service receipt, revision and creation time,
with separate pending/failure feedback. These receipt displays last for the
session; missing receipt does not imply that older backups do not exist.
Demo does not display Personal confirmations or expose the service-backup action.

No verified restore receipt is tracked by this UI, so the restore line says
Not tested. A successful backup or cloud save is not presented as a restore test.

## Recovery

This is a compatible presentation/session-metadata change with no database or
cloud migration. Source rollback preserves current data, submission/document
readers and existing reward/finance rules. Keep database/files backup independent
from source packages; do not restore old facts merely to undo presentation.
