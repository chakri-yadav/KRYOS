# Analytics scope and evidence presentation

## Ownership and metric contract

Application totals use the existing canonical nonvoided submission projection by
applied operating date. Reapplications have separate rows; postings are not used
as the counting unit. Follow-ups require distinct explicit completed activity
IDs, scoped by occurred operating date, excluding voided activity. Interview
figures are the current stage of submissions in the selected cohort, not
interviews occurring in that period. Existing review receipts and core checklist
coverage remain their own owners; this release adds no mastery or readiness score.

## Interaction

Application work remains the default local view. Progress uses a full-width
report with three headline measures. Today and calendar-week presets hide the
date form; Custom reveals Applied from/Through. Invalid input leaves the last
valid report intact. Longer views group by labelled seven-day periods.

Local bars open exact contributing submissions in an equivalent table. A record
opens through its existing ID; returning preserves reporting dates, drilldown
and focus. Current stage breakdown remains optional. Hosted bars open contributing
aggregate snapshots with source revision and receipt time; missing dates remain
unknown and received zeroes stay zero. Optional comparisons remain disclosed.

Cross-page evidence starts with one dated count and source state. Details retain
direct/source counts, conservative overlap explanation, earlier dates and receipt
information. Disclosure survives refresh; a source refresh defers replacement
while a panel control is focused. Selected-day earned credits remain distinct
from the current wallet.

## Export and transfer boundary

Counts exports allow only date, workspace identity, source revision and submitted
count. Local export reads the saved source and is disabled while a save is pending,
loading or disconnected. Hosted export includes received dates only. A download
is neither a cloud import nor an award. The existing explicit handoff path,
snapshot identity, receipt verification and reward rules are unchanged.

## Storage and recovery

No schema, persisted fact, reward rule or migration changes. Browser reporting
state is presentation only. Jobs, contacts, descriptions and documents remain
local. Roll back presentation to a compatible source distribution while retaining
the submission-history and document-version readers. Data backups are separate
from source packages; do not restore older records to undo this UI release.
