# KRYOS 0.6.0 — Assistant Capture and Safe Sync

Release date: 2026-09-26

## Product reason and user problem

The founder needs to speak or write once and have truthful progress appear in the Personal app without repeating manual entry on the phone. Stale mobile or desktop data must not erase a newer update.

## Included scope

- Assistant ingestion for dated Journal entries, Rhythm water/habits, Actions, Career progress/checklist completion, and Inner Command observations.
- A Personal-only, revocable assistant token; a request receipt and stable idempotency key prevent duplicate effects.
- Atomic Supabase request/event/change-log storage with revision-checked task and career block writes.
- Browser cloud settings to create or revoke assistant access and cache-busted 0.6.0 assets.

## Explicit exclusions

- No automatic reward-day review or credit award. Rewards continue to derive from evidence and require the existing review step.
- No automatic interpretation of ambiguous claims, event reversal, or field-level merge of simultaneous offline edits.
- No interview-demo scope; Demo profile cannot issue assistant access.

## Data ownership and sync/backup impact

Journal, Rhythm, Actions, and observations remain in the Personal `tasks` block; Career checklist state remains in `career`. The migration adds revisions and assistant audit tables without replacing or deleting existing payloads. The first migration keeps old clients writable; a separate post-release cutover requires revision-aware RPC writes. Existing Personal export/import remains the recovery path. A verified backup and restore drill are release gates.

## Acceptance criteria

- The assistant can send a dated, evidence-backed request with a private token and receive an accepted receipt.
- Retrying the same request produces no duplicate effect; a changed request with the same key is rejected.
- The resulting Personal data appears after refresh on desktop and iPhone; stale browser writes conflict instead of erasing it.
- Missing or revoked tokens are denied; Demo data is untouched.
- Existing Actions and Career edits still work through the rollout.

## QA record

- Local: JavaScript syntax checks and 48 automated tests passed.
- Production: additive migration applied; required schema/function objects verified; deployed Edge Function returned HTTP 401 with no token. The requested September 25 journal was accepted under the Personal profile, a same-key retry returned `duplicate: true`, and the cloud holds exactly one matching entry.
- Pending: revoked-token rejection, desktop and iPhone convergence, backup/restore drill, post-release policy cutover.

## Known limitations and next milestone

The assistant connector currently runs as a local command-line bridge, not an automatically installed tool in every conversation. Offline operation outbox, event correction/reversal, and automated reward review are later bounded milestones. The 0.6.0 tag and GitHub Release should be published only after the pending QA gates pass.
