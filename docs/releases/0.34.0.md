# Reward, finance and storage clarity

19 October 2026 · local 0.34.0 / hosted 0.51.0 · this distribution 0.34.0.

## Product reason and scope

Make dated evidence, current balances and save confirmation easy to distinguish.
See [supporting-page contract](../design/supporting-page-clarity.md).

Rewards reuses its shared day summary beside current eligibility, exposes all
blocking conditions and discloses retained assessment changes. Money distinguishes
entry dates from current positions, retaining the hosted reconciliation workflow
and local record controls. Settings shows scoped destinations, actual recorded
confirmation times, backup receipts and explicit unknown restore verification.

## Data and sync impact

No schema, scoring, catalogue, financial calculation or production record change.
Redemption request/retry and server authorization remain unchanged. Session-only
confirmation metadata is recorded after existing successful responses; it is
scoped by account/mode/workspace. A requested JSON download is not a verified
file save or restore. Local backup creation requires an accepted service receipt.
No automatic Marketing transfer or new cloud operation is introduced.

## Acceptance and QA

235 local / 344 public automated checks pass. New fixtures exercise simultaneous
reward blockers, audit effects/reason absence, account-scoped receipts, successful
save vs rejected/signed-out paths, dirty-state precedence, local source readiness,
dated finance projection and exact cents. Local backup tests reject unsaved state
and invalid receipts while retaining an earlier valid receipt.

Isolated desktop walkthroughs cover both builds: historical wallet/date behavior,
single shared summary, evidence jump, all reward gates, dated payment entry,
unchanged current balance, hosted ledger position across date changes, pending
save/receipt states, preserved credential drafts and five widths (320–1440).
Disposable local service verifies backup success then failure with retained prior
receipt. Existing five-page layout/navigation and 15 critical rendered contrast
pairs pass in both builds; analytics regressions pass. Screenshots reviewed.
External account writes are blocked for synthetic verification.

## Limits and recovery

Receipt displays are session-only. Missing timestamps remain unrecorded; no full
restore or physical-phone/screen-reader audit is claimed. Local and hosted Money
retain their different existing owners rather than migrating data between them.
Rollback compatible source while preserving current records and version readers;
data backups remain independent. Next: explicit render composition and lifecycle.
