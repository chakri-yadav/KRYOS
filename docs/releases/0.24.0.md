# KRYOS 0.24.0 — Marketing cloud sync and assistant batch import

## User outcome

Marketing batches and per-application records are stored in the signed-in Personal
Supabase profile instead of remaining only in one browser. The assistant can submit
one complete validated Marketing batch through the existing assistant-ingestion
function and receive an idempotent acceptance receipt.

## Data and behavior

- Add the `marketing` block to the existing sync model and use compare-and-swap
  revisions for browser writes, as for Tasks and Career.
- Refresh Marketing records through the existing Realtime and foreground refresh
  paths. Preserve full batch/posting fields, including unknown source details.
- Add the `marketing.batch.import` assistant operation. It preserves the full batch,
  defaults application tracking fields, records an audit event, and returns the
  accepted posting count and new block revision.
- Retry the identical request with the same idempotency key; the backend returns the
  original receipt rather than inserting another batch. Reusing a key with different
  content is rejected.
- Résumé/supporting-file bytes remain browser-local. This release syncs job and
  application metadata only; cross-device file storage is a separate follow-up.

## Deployment order

1. Apply `supabase/migrations/20261007120000_marketing_cloud_assistant_import.sql`.
2. Deploy the updated `kryos-ingest` Edge Function.
3. Publish the 0.24.0 GitHub Pages app.
4. Use a clearly fictional three-posting batch. Verify the accepted receipt, Marketing
   block revision, page display after refresh, and idempotent same-key retry.

Do not announce the cloud import as live until the migration, function, browser app,
and authenticated round-trip have each been verified. No private postings, resumes,
journal content, or assistant credentials belong in GitHub.
