# Settings render lifecycle

Local 0.34.1 / hosted 0.51.1. Compatible presentation correction; no schema migration.

Settings now enters one explicit composition sequence through its base renderer:
capture view state, read its existing model, render base, render owned sections,
restore editing context. The presentation adapter no longer reassigns the global
Settings renderer. Before the adapter loads, the base entry remains available.

While editing a text control, dirty text inputs are retained in transient memory
across that synchronous render only. No draft is written to storage or sent to a
service. Account/mode identity must match before restoration. File inputs are not
restored. Focus, text selection, reading position and the existing release/backup
disclosures are preserved. Status-only updates still target their owned card.
There are no new listeners, timers, domain mutations or subscription owners.

238 local / 347 public automated checks pass. Isolated browser checks verify
repeated full renders with a draft and text selection, one storage panel, retained
disclosures, existing save/backup flows and five desktop viewport widths.
External account writes are blocked in synthetic verification.

This is the first page-sized composition migration, not completion of the broader
lifecycle program. Other render wrappers and evidence polling remain until their
transition coverage is verified. Restore compatible previous source versions
(local 0.34.0 / hosted 0.51.0) without rolling back data. No reward, financial,
roadmap or Marketing record changes are required.
