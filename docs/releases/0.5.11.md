# KRYOS 0.5.11 — Career Sync Ordering

Release date: 2026-09-25

## Product reason

Career completion is durable personal evidence. Opening KRYOS on a phone must never let initialization work race ahead of cloud recovery or make completed desktop problems disappear.

## Root cause

The Career roadmap migrations ran during application startup and scheduled a cloud save immediately. On a phone with empty or stale local storage, that write could reach Supabase before the first cloud read finished. The freshness logic could be correct and still receive already-overwritten Career data.

## Included scope

- Keep required Career migrations local during initialization.
- Await the first signed-in cloud reconciliation before allowing a migration autosave.
- Apply required migrations again after an accepted cloud Career payload is loaded.
- Save the post-reconciliation migration only when no conflict was detected.
- Update browser asset versions so iPhone Safari requests the corrected startup code.

## Data, sync, and backup impact

No Supabase schema or backup format changes are required. The change only controls operation ordering during startup. Existing Career payloads and per-section cloud checkpoints remain compatible.

## Acceptance criteria

- A phone cannot push startup-generated Career data before its first cloud read finishes.
- Completed desktop Career checklist items remain completed after the phone opens.
- Required DSA and API roadmap migrations are preserved after cloud recovery.
- A detected conflict prevents the deferred migration write.
- Local-only use remains available while signed out or offline.

## QA performed

- JavaScript syntax validation.
- Full automated regression suite.
- Browser regression for Career, Actions, persistence, and all active workspaces.
- Static startup-order regression that rejects pre-reconciliation Career migration writes.

## Known limitations

The system still performs section-level conflict protection rather than field-level merges. If cloud data was overwritten before this release, the desktop copy must remain available so it can be pushed back to the cloud.
