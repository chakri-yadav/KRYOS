# KRYOS 0.5.9 — Mobile Actions and Live Sync

Release date: 2026-09-25

## Product reason

Actions is the most frequently updated mobile surface. It must be fast enough to capture, reprioritize, complete, and reopen commitments without layout friction or uncertainty about whether another device is current.

## User problem

The mobile Actions hierarchy consumed excessive vertical space, some controls competed visually, and cross-device updates could remain stale until launch, resume, or manual refresh. Safe updates also forced a full page reload.

## Included scope

- Compact the mobile Actions header, capacity command, filters, capture form, cards, and controls.
- Preserve add, edit, status, complete, reopen, priority, domain, next-action, and deadline workflows.
- Correct mobile card geometry around 44-point completion, status, and edit controls.
- Show accurate live, saving, synchronized, local, and unavailable language.
- Listen for Supabase sync-block changes in realtime when available.
- Check immediately when entering a core mobile page and every five seconds while visible as a fallback.
- Hydrate safe remote updates into the running app without reloading the page.
- Keep the existing conflict rule: concurrent local and remote changes are preserved for review rather than silently overwritten.

## Explicit exclusions

- No field-level multi-device merge.
- No background synchronization after the browser suspends the page.
- No notification or service-worker installation.
- No Supabase schema migration.

## Data, sync, and backup impact

Actions continue to use the existing Tasks sync block. Local saves remain immediate and cloud writes remain debounced. Realtime and fallback checks only change delivery speed; storage keys, payload schema, backup, and restore formats are unchanged.

## Acceptance criteria

- Actions is usable without horizontal overflow at 430 by 932 points.
- Add, edit, status, complete, and reopen controls remain touch-safe.
- Local changes visibly enter saving and synchronized states.
- Safe remote task changes appear without a full page reload.
- Realtime events request a freshness check, with an immediate page-entry check and five-second fallback while visible.
- Concurrent local and remote changes are not silently replaced.
- Desktop Actions behavior remains intact.

## QA performed

- JavaScript syntax validation and full automated test suite.
- Existing desktop Actions create, edit, complete, and persistence browser regression.
- iPhone 15 Plus layout, add form, edit dialog, status, completion, reopen, reload, and overflow checks.
- Static verification of realtime subscription, fallback interval, and in-place hydration paths.

## Known limitations

Supabase Realtime requires the sync table to be included in the project’s realtime publication. The canonical schema now enables it when rerun. Until then, the visible-page fallback still checks every five seconds. Browser suspension can delay checks until KRYOS returns to the foreground.
