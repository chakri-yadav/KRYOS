# KRYOS 0.15.0 — Marketing workspace shell

- Release date: 2026-09-28
- Product reason: establish a distinct, low-friction Marketing workspace under Career Launch before implementing batch import and job-record persistence.
- User problem: job-search batches and application records need a focused home without turning KRYOS's existing Career Launch activity tracker into an overcrowded spreadsheet.
- Included: Career Launch entry button; separate Marketing identity and layout; current-batch empty state; searchable saved-role list shell; in-app return; browser Back/Forward handling; shared live KRYOS cloud-state display.
- Explicitly excluded: batch import, job-search filtering, actual saved-role records, application-status editing, résumé uploads, and Marketing-specific cloud persistence.
- Data impact: none. No existing Career Launch, Personal, or Demo records are migrated, edited, or synthesized. The shell displays no fake jobs.
- Sync/backup impact: none to stored data or backup schema. The sync badge reflects the existing app-wide cloud connection only; it does not claim that Marketing records have synced.
- Acceptance criteria: Marketing opens from Career Launch as a visually separate workspace; the return control and browser history route back to Career Launch; batch and saved-role empty states are clear; the shared cloud badge reflects the current app state; no unrelated mobile workflow or data model changes.
- QA performed: `node --check` passed for `app.js`, `launch.js`, and `marketing.js`; `git diff --check` passed; an isolated preview confirmed the desktop screen hierarchy and empty states render. The locked Personal app preview was not unlocked, so in-app Back/Forward interaction was not manually exercised.
- Mobile scope: the new workspace has responsive styling, but no device-specific mobile verification was performed; existing KRYOS mobile views and navigation were not changed.
- Known limitation: the visible search field is a shell only until saved-role records are implemented. No job or résumé data can be imported or saved in this milestone.
- Next milestone: import the full user-provided search batch, preserve raw posting fields, and make selected roles searchable and editable without altering existing Career Launch evidence.
