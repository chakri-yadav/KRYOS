# 0.28.0 — Daily Commitment commitments

Inner Command supports a separate 48-day cycle with Day 0 preparation, a complete devotional outline, individual boundary/practice records, dated must-do tasks, and reviewed battle outcomes. Quantity commitments and existing Actions share task identity. Reopening recalculates the day; late reporting uses the occurrence date. Multiple breach selections, corrections, and previous-cycle history are retained.

The browser and deployed assistant ingestion use the same battle engine. Supported assistant operations are `commitment.cycle.start`, `commitment.task.assign`, `commitment.plan.empty`, `commitment.item.set`, `commitment.task.progress`, `commitment.task.correct`, `commitment.breach.record`, `commitment.breach.correct`, and `commitment.day.review`. Requests retain existing evidence, idempotency, transactional commit, and revision protections.

Use the request's `local_date` for the affected day. Task progress sets an absolute total; it is not an increment. Assignment can link `actionId` or create a shared action. Corrections require a reason. Review occurs after the assigned calendar day ends. Unknown facts remain open. No new reward points are introduced.

Validation covers DST dates, unknown/missed distinctions, quantity targets, multiple breaches, action completion/reopening, late occurrence dates, revision conflicts, retry duplication, and assistant projection.
