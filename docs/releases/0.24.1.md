# KRYOS 0.24.1 — Marketing cloud reconciliation

## Summary

Fix Marketing refresh so cloud-imported job batches remain visible when this browser already contains a separate local batch.

## User-facing changes

- A cloud Marketing batch is merged with separate local batches instead of being skipped as a whole-block conflict.
- When newly received cloud data is not the currently selected batch, Marketing selects the first cloud batch so the import is immediately visible.
- Cloud Versions now lists Marketing.
- Marketing copy distinguishes synced batch/application data from browser-local uploaded file bytes.

## Technical and data changes

- Merge by stable batch ID. Remote batches are listed first; local-only batches are retained and queued for revision-checked sync.
- Conflicting edits to the same batch ID preserve the local version and increment the existing conflict signal. Neither copy is silently discarded.
- No database schema, Edge Function, or existing cloud batch changed in this patch.

## QA

- Validate separate-batch merge and same-ID conflict behavior with unit coverage.
- Run cloud-sync/deployment contract checks and the full automated suite.
- Confirm GitHub Pages loads the versioned assets after merge.
- The live Supabase import receipt already confirms three fictional test postings in Marketing batch `marketing-demo-batch-20261007-v1`, revision 1.

## Known risks

- Uploaded file bytes still remain in the browser and are not cross-device synced or backed up.
- When the same batch ID has different contents, the existing conflict indicator requires review; the merge does not guess which edit is correct.
