# KRYOS 0.22.0 — Resume Interview Mastery System

## Purpose

Replace the preliminary five-topic speaking outline with the supplied interview
mastery curriculum. The goal is interview-level understanding and clear spoken
answers about the user's actual resume claims—not an exhaustive study of every
topic in a private audit.

## Product change

The Career roadmap is organized into five layers and 20 modules:

1. Resume claim control: career/system map, evidence boundaries, ownership, and
   tiered study depth.
2. Shared technical foundations: HTTP/API contracts; testing and CI/CD; SQL and
   PostgreSQL; caching; transactions and concurrency; asynchronous/distributed
   reliability; authentication and authorization; observability; reliability
   hardening; partitioning/reporting; Docker/Jenkins.
3. Bullet-specific deep dives: a reusable 12-field card per resume claim, linked
   only to relevant shared concepts.
4. Interview speaking: 10-second, 30-second, 90-second, and invited deep-dive
   answers; answer grammar; follow-up families; system-design bridge; behavioral
   examples.
5. Mock interview and retrieval practice: closed-note explanation, targeted
   follow-ups, short answer delivery, random probing, delayed recall, and repair.

Depth is claim-led: Must Speak, Must Understand, Awareness Only, or Do Not Study
for this Resume. The roadmap contains general prompts, not private resume text,
company history, or unverified implementation details. Actual experience,
learning models, assumptions, and unknowns must remain distinct.

## Migration and data

- Upgrade `roadmap-resume-interview-speaking` in place; do not create a duplicate.
- Preserve unrelated roadmaps and activity history. Preserve completed checks
  whose exact checklist text remains unchanged.
- No database schema change. The signed-in app persists the migrated Career
  state through ordinary revision-checked sync when opened.

## Verification and limitations

- Roadmap tests verify five layers, 20 modules, unique checklist IDs, the 12
  distinct bullet-card fields, and the claim-led practice design.
- Migration tests verify in-place upgrade, idempotency, and progress/history
  preservation.
- Personal cloud persistence is not claimed until a signed-in browser opens
  this release and completes Career synchronization.
