# KRYOS 0.9.0 — Living Money ledger

Reason: a frozen settlement cannot represent interest accruing on a carried Amex balance.

The Personal Money page now separates Amex card shares from direct reimbursement, records subsequent card payments by payer and attributed share, accepts actual statement interest, allocates it using daily balance weights (or an explicitly entered split), and compares the derived total with the issuer's closing balance. A guarded APR projection is labeled as an estimate and is never added to the ledger. Mistaken ledger entries can be corrected out and restored without deleting the audit trail.

Data remains in the existing private task sync block. The prior checkpoint is the opening balance; historical interest within it is not replayed. No schema migration or paid service is required. Entry changes use the existing revision-safe task sync path; failed cloud writes remain visible through the app's sync state.

QA: unit tests of ledger invariants, browser Money flow, and the complete local test suite. Known limits: the user's account-specific APR and actual later statements must be recorded before an exact future interest charge can be shown; forecasts pause after intervening events; same-APR issuer payment allocation may differ from the private split and must be reconciled against statements. Import of raw statement transactions is not included.
