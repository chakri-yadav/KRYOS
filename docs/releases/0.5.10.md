# KRYOS 0.5.10 — Cross-device Recovery

Release date: 2026-09-25

## Product reason

Completed desktop Career work must appear on the phone without the phone looking like a new installation. Cross-device confidence is more important than cosmetic polish when KRYOS is used as a personal progress record.

## Root cause

A new phone generated empty starter data with a current timestamp. The previous freshness rule compared that timestamp with the cloud payload timestamp and could therefore treat empty local data as newer than real desktop progress. One global sync timestamp also made unrelated sections interfere with each other's conflict decisions.

## Included scope

- Track the last accepted cloud version independently for Foundation, Career, Actions/Tasks, and Journal.
- Recover cloud data on a device that has no established checkpoint.
- Prefer a cloud Career block when it contains more actual completion evidence than an uncheckpointed local copy.
- Continue preserving both copies when established local and cloud versions changed concurrently.
- Record per-section checkpoints after automatic saves, full pushes, refreshes, and manual pulls.
- Change asset cache keys so mobile Safari loads the corrected code immediately.

## Data, sync, and backup impact

No application payload or Supabase schema migration is required. Per-section cloud checkpoints are local synchronization metadata and remain excluded from backups and cloud payloads. Existing accounts acquire checkpoints automatically.

## Acceptance criteria

- A blank phone signed into the same personal account restores completed desktop Career problems.
- A stale, uncheckpointed phone accepts a cloud Career copy with greater completion evidence.
- Career and Actions cloud writes store their own accepted remote versions.
- Established concurrent edits are not silently overwritten.
- The application continues working locally when Supabase is unavailable.

## QA performed

- JavaScript syntax validation.
- Full automated regression suite.
- Static regression coverage for recovery logic, per-section checkpoints, realtime fallback, and deployment ordering.
- Cache-version audit across all application assets.

## Known limitations

KRYOS still resolves conflicts at section level rather than merging individual fields. A browser suspended by iOS cannot synchronize until the page resumes, at which point the foreground refresh runs.
