# Product Principles

These principles guide every KRYOS feature.

## 1. Trust Before Scale

Do not add sync, AI, or complex analytics before local data is trustworthy.

## 2. One Page, One Job

Each page must own a clear responsibility.

- Foundation owns why.
- Career owns roadmaps.
- Today owns execution.
- Habits owns consistency.
- Journal owns containment.
- Progress owns analytics.
- Settings owns privacy and data control.

## 3. Progress Must Come From Evidence

Progress should read from real actions, not motivational decoration.

## 4. Mobile Is Field Mode

Mobile should support quick input and quick checkoff. It should not become a full desktop replacement.

## 5. Editing Must Be Intentional

The app should not feel like a form everywhere. Visual pages should stay visual unless the user deliberately enters edit mode.

## 6. No Duplicate Features

If two pages do the same job, one of them is wrong.

## 7. Private By Default

Personal data should never be mixed with demo data or public material.

## 8. Motivation Without Noise

Visuals should create clarity and momentum. They should not become decoration.
